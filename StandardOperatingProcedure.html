SOP • 02
01 • PURPOSE

Why This SOP Exists

The purpose of this SOP is to define how the IIC Core Team converts responsibility into action without creating an unnecessary hierarchy between roles.

One Council. Multiple Responsibility Areas.

Each coordinator owns a specific responsibility area. Roles are not isolated departments. They are connected parts of one operating system.

The IIC Convenor ensures that these responsibility areas receive the right inputs, move through a defined process, produce useful outputs and remain continuously reviewed.

Operating Principles

Ownership

Every responsibility area must have a clear owner and measurable output.

Collaboration

Coordinators work together whenever an activity crosses multiple responsibility areas.

Accountability

Work should be visible, trackable and reviewable.

Execution

Ideas are valuable only when converted into action and outcomes.

Documentation

Every major activity should leave behind usable records and evidence.

Improvement

Feedback should continuously improve the system.

The IIC Operating Equation

INPUT Ideas, requests, opportunities
→
PROCESS Plan, assign, coordinate
→
OUTPUT Events, connections, outcomes
→
CONTROL Review, measure, document
→
IMPROVE Feedback & iteration

02 • SYSTEM CONTROL

IIC Convenor

The Convenor is the system integrator of the IIC Core Team. The role is not designed as a traditional command hierarchy.

👑 IIC Convenor

System Coordination • Review • Integration • Control
SYSTEM OWNER
01. Build the System Create processes through which ideas and responsibilities move from input to output.
02. Connect KRAs Ensure different responsibility areas work together instead of functioning in silos.
03. Review Progress Monitor whether responsibilities are being converted into actual outputs.
04. Remove Bottlenecks Identify delays, confusion, duplication or resource gaps and help resolve them.
05. Coordinate Resources Connect people, mentors, speakers, students, opportunities and institutional resources.
06. Maintain Standards Ensure activities follow agreed processes, timelines and documentation standards.
07. Review Outputs Check what was achieved, what was missed and what should happen next.
08. Improve the System Use feedback and performance data to improve how IIC operates over time.

Convenor's Core Question

"What input has come in, who is processing it, what output is expected, what has actually happened, and what needs to be improved?"

SOP • 04
03 • WORKFLOW

How IIC Work Moves

Every major activity should pass through a simple, repeatable operating cycle.

1
INPUT

A student idea, opportunity, requirement, event proposal, partnership opportunity, innovation challenge or institutional need enters the system.

2
IDENTIFY RESPONSIBILITY

The relevant KRA owner is identified. If multiple KRAs are involved, a primary owner and supporting roles are defined.

3
PLAN

Define objective, people involved, timeline, resources, expected output and success measure.

4
EXECUTE

The responsible team carries out the activity while coordinating with other relevant KRAs.

5
OUTPUT

The activity produces a defined outcome: event, participant engagement, startup lead, internship opportunity, innovation submission, content, report, connection or other result.

6
CONTROL & REVIEW

The output is reviewed for completion, quality, documentation and measurable impact.

7
LEARN & IMPROVE

Feedback, problems and lessons are recorded and used to improve the next cycle.

Control & Review System

06 • CONTROL

How the System Stays on Track

The purpose of control is not to micromanage coordinators. It is to make sure work does not disappear between planning and execution.

Weekly

  • What is currently active?
  • What is blocked?
  • What support is required?
  • What is due next?

Monthly

  • What was completed?
  • What output was generated?
  • What opportunities were created?
  • What needs improvement?

Core Control Dashboard

INPUT Ideas & opportunities received
ACTIVE Activities in process
OUTPUT Completed outcomes
IMPACT Measured value created

Important Rule

No activity should exist only in someone's memory.

Important work should have an owner, deadline, status and final output recorded in the IIC system.

Recommended Digital System

01 • INPUT

Google Form / Website submission for ideas, opportunities, requests and proposals.

02 • PROCESS

Central task board with owner, deadline, priority and status.

03 • OUTPUT

Reports, events, connections, content, submissions and measurable outcomes.

04 • CONTROL

Dashboard showing pending, active, completed and delayed work.

05 • DOCUMENT

Central archive for photographs, reports, attendance and evidence.

06 • REVIEW

Monthly review of performance, problems and improvements.

Cross-Functional Collaboration

07 • COLLABORATION

No Role Works in Isolation

Responsibility areas remain distinct, but activities can flow across multiple KRAs.

Example: Student Startup Pitching Activity

A startup pitching activity may involve the Start-up Coordinator for startup identification, Graphics & Creative for branding, Social Media for promotion, Alumni for founder connections and Documentation for records.

The Convenor ensures that the complete chain works together and that the final output is captured.

Collaboration Rule

A
PRIMARY OWNER

One KRA owns the outcome.

B
SUPPORTING KRAs

Other responsibility areas provide specific support.

C
COMMON OUTPUT

Everyone works toward one defined result rather than separate individual activities.

D
REVIEW

The Convenor reviews the complete activity, not only one person's contribution.

The Goal

Not "Who is senior?"
But "Who owns what, what support is required, and what outcome are we creating?"

Accountability Standards
SOP • 10
09 • ACCOUNTABILITY

Core Team Working Standards

The purpose of accountability is to create reliability, not pressure.

Take ownership of assigned responsibility.
Communicate delays early.
Keep information updated.
Respect deadlines.
Ask for help when required.
Do not duplicate another role's work unnecessarily.
Give credit to contributors.
Maintain professional communication.
Document completed activities.
Focus on outcomes, not only activity count.

Escalation Principle

If a coordinator is blocked, the objective is not to blame the person. The issue should be identified, communicated and solved through the system.

Blocked work → Communicate → Support → Resolve → Continue

What Success Looks Like

Students

More students discover opportunities to innovate, build, participate and connect.

Core Team

Members gain real experience in ownership, leadership, coordination and execution.

IIC

Activities become organised, measurable, documented and continuously improving.

60 Days
